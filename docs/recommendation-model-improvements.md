# RecRec 추천 모델 구현 및 개선 내역

## 1. 서비스 목표와 현재 구조

서비스는 사용자가 탐색하는 **하나의 카테고리 안에서**, 상품 선택·피팅·찜 이력을 바탕으로 관심 상품을 추천한다. 현재는 실제 고객 로그가 부족하므로 상품 이미지로 디자인 유사성을 계산하고, 이를 활용해 가상 고객의 행동 데이터를 생성했다.

**이미지 임베딩은 합성 데이터 생성에 사용한다. 기본 RecRec은 이미지 벡터를 직접 입력받지 않으며, 생성된 행동을 통해 상품 관계를 간접적으로 학습한다.**

```text
상품 이미지 → CLIP 이미지 임베딩
                  ↓
       디자인 취향을 가정한 합성 행동 데이터
                  ↓
       상품 ID 임베딩 + 행동 임베딩
                  ↓
         행동·최근성 가중 평균
                  ↓
         RecRec 사용자 선호 재귀 보정
                  ↓
             후보 상품 점수
```

| 구성 요소 | 현재 상태 |
|---|---|
| 이미지 연결 및 임베딩 | 134개 상품 처리 완료 |
| 이미지 기반 합성 데이터 | 9,000개 세션 생성·검증 완료 |
| 기본 RecRec | ID 기반 상품 표현과 행동·최근성 pooling |
| SBERT | 미적용, 필수 구성 요소 아님 |
| 이미지 벡터의 RecRec 직접 입력 | 미적용 |
| 실제 고객 로그 기반 품질 검증 | 미완료 |

## 2. 기존 구현에서 개선한 부분

### RecRec에 추가한 내용 요약

**RecRec의 재귀 보정 구조를 유지하면서, 재귀 보정에 전달하는 행동 요약 방식과 학습 데이터 생성 방식을 개선했다.**

| 구분 | 추가·개선한 내용 | 적용 상태 |
|---|---|---|
| 모델 내부의 이력 집계 | 단순 평균을 행동 강도 × 최근성 가중 pooling으로 변경 | 기본 모델에 적용 |
| 행동 표현 | 피팅을 추가·제거로 분리해 행동 임베딩 확장 | 기본 모델에 적용 |
| 학습 데이터 생성 | CLIP 이미지 유사도로 가상 고객의 디자인 취향과 행동 생성 | 현재 합성 데이터에 적용 |
| 선택적 상품 표현 | 상품 속성의 해시 벡터를 ID 임베딩에 결합하는 콘텐츠 인코더 | 구현되어 있으나 기본 모델에서는 비활성 |

가중 pooling으로 만든 벡터는 RecRec의 재귀 보정을 거쳐 최종 사용자 선호 표현으로 사용된다. 후보 점수는 이 선호와 학습된 상품 임베딩으로 계산한다. CLIP은 데이터 생성 단계에서 활용하므로, 현재 구현을 “RecRec에 CLIP 이미지 벡터를 직접 결합했다”고 표현하지 않는다.

발표나 구현 소개에는 다음과 같이 요약할 수 있다.

> RecRec의 재귀 보정 구조를 유지하면서, 행동 강도와 최근성을 반영하는 가중 pooling을 적용했다. 또한 상품 이미지의 CLIP 임베딩을 활용해 단일 카테고리 내 디자인 취향을 반영한 합성 행동 데이터를 생성했다.

### 행동 강도와 최근성 반영

기존 모델은 상품·행동 임베딩을 단순 평균했다. 오래된 행동과 최근 행동의 집계 비중이 같고, 선택보다 찜을 더 강한 관심으로 취급하는 규칙이 집계에 직접 반영되지 않았다.

현재는 행동 가중치와 최근성 가중치를 곱한 가중 평균을 사용한다. 최근에 강한 관심을 보인 상품이 이력 표현에 더 크게 반영된다. 이는 서비스 가정을 구현한 것이며, 추천 성능 향상 여부는 별도 평가가 필요하다.

### 피팅 추가와 제거 구분

기존 `FITTING`을 `FITTING_ADD`, `FITTING_REMOVE`로 분리했다. 행동 유형은 PAD를 포함해 6개다. 구형 행동 데이터와 5개 행동 임베딩의 체크포인트는 현재 체계에 맞게 전환·재학습해야 한다.

### 이미지 기반 데이터 생성 추가

기존 생성기는 가상 고객의 Zone·카테고리·하위 카테고리 선호와 동적 행동 규칙을 사용했다. 새 생성기는 하나의 카테고리 안에서 이미지 기반 디자인 취향을 중심으로 상품을 선택한다.

기존 `src/synthetic_generator.py`는 행동 확률 함수와 행동 성향 설정을 재사용하기 위해 유지한다. 이미지 기반 생성 진입점은 `src/synthetic_image_generator.py`다. 과거 실행 파일과 체크포인트의 `v2` 이름도 정리했다.

### 이미지 처리와 유사도

`src/image_similarity.py`는 다음 순서로 처리한다.

1. 이미지 방향을 보정하고 투명 배경을 흰색으로 합성한다.
2. 정사각형 여백을 추가해 중심 crop 과정에서 상품이 잘리는 것을 방지한다.
3. 고정된 `openai/clip-vit-base-patch32`로 512차원 이미지 벡터를 계산한다.
4. 벡터를 L2 정규화하고 내적으로 코사인 유사도를 계산한다.

CLIP을 상품 데이터로 추가 학습하지 않는다. 모델 파일은 다운로드하지만 상품 이미지는 로컬에서 처리한다.

| 산출물 | 용도 |
|---|---|
| `artifacts/image_similarity/embeddings.pt` | 전체 벡터, 상품 매핑, 이미지 hash, 모델 revision |
| `artifacts/image_similarity/neighbors.json` | 같은 카테고리 내 유사 상품 상위 5개 |
| `artifacts/image_similarity/report.html` | 기준 상품과 이웃 상품의 이미지 비교 |

보고서는 자기 자신을 제외한 같은 카테고리의 이웃을 보여준다. 합성 생성기는 상위 5개 목록만 사용하는 것이 아니라 **전체 이미지 벡터로 세션 후보의 유사도를 계산**한다.

대표 결과에서는 가방·티셔츠·운동화의 형태가 유사한 상품들이 연결됐다. 하의·액세서리에서는 색상·패턴이 비슷한 다른 종류도 섞였다. 이 관찰은 정량적인 추천 품질 검증을 대신하지 않는다.

상품 ID `31`, `127`은 이미지 파일 내용이 동일하지만 별도 상품으로 유지한다. 설치와 실행 세부 사항은 [이미지 유사도 문서](image-similarity.md)를 참고한다.

## 4. 이미지 기반 합성 데이터 생성

### 카테고리와 세션 취향 설정

세션마다 카테고리 하나와 가상 고객의 성별을 정한다. 같은 카테고리에서 해당 성별 또는 UNISEX 상품만 후보로 사용한다. 카테고리별 세션 수는 균등하며, 실제 고객 분포를 추정한 비율은 아니다.

후보 중 기준 상품 하나를 뽑아 세션 전체의 숨겨진 디자인 취향으로 사용한다. 이 상품은 반드시 첫 번째로 선택되는 상품도, 반드시 선택해야 하는 정답도 아니다.

기준 상품과 후보 상품의 코사인 유사도를 세션 후보 전체에서 min-max 정규화해 취향 적합도를 계산한다. 선택으로 후보가 줄어도 초기 정규화 기준을 유지한다.

### 다음 상품 선택

| 선택 점수 구성 | 계수 | 역할 |
|---|---:|---|
| 고정 취향 적합도 | 0.80 | 세션 전체의 디자인 취향 유지 |
| 직전 상품과의 유사도 | 0.20 | 현재 비교하는 상품 반영 |
| 이전 행동 피드백 | 0.15 | 유지된 관심과 철회 반영 |

피드백은 별도의 가감 항이므로 세 계수는 확률 비율이 아니다. 점수를 세션별 온도 `0.16~0.28`의 softmax로 변환한 뒤 균등 탐색 확률을 섞는다.

| 행동 성향 | 균등 탐색 확률 |
|---|---:|
| DECISIVE_BUYER | 10% |
| FASHION_EXPLORER | 20% |
| BROAD_EXPLORER | 35% |

항상 가장 비슷한 상품을 선택하지 않는다. 세션마다 최소 두 상품을 선택하며, 최대 선택 수는 후보 수의 약 70%와 14개 중 작은 값이다. 같은 상품은 재선택하지 않고, 하위 카테고리는 강제 제한하지 않는다.

### 피팅·찜과 관심 철회

선택 상품의 취향 적합도와 기존 행동 성향을 이용해 피팅·찜 확률을 계산한다. 제거는 해당 추가 이후에만 발생한다.

다음 선택의 피드백은 최종 유지 상태를 반영한다. 제거된 피팅·찜은 유지 중인 긍정 상태로 남기지 않으며, 제거에 따른 감쇠도 적용한다. 이는 **생성기의 규칙**이다. RecRec pooling에서 이전 추가가 자동 취소된다는 의미는 아니다.

실제 timestamp는 없고 이벤트 순번만 저장한다. 기준 상품·탐색 확률 등의 메타데이터는 생성 검증용이며 RecRec 학습 입력에는 포함하지 않는다.

## 5. RecRec이 학습하는 정보

### 학습 입력과 정답

모델은 과거 상품 ID와 행동 종류로 다음에 선택할 상품 ID를 예측한다. 순서는 이력 구성과 최근성 계산에 사용된다.

```text
세션: A 선택 → A 피팅 → A 찜 → B 선택 → B 피팅 → C 선택

샘플 1: A의 선택·피팅·찜 이력            → 정답 B
샘플 2: A의 행동 이력 + B의 선택·피팅 이력 → 정답 C
```

정답은 다음 `PRODUCT_SELECT` 상품이다. 구매나 만족도를 직접 예측하는 데이터는 아니다.

세션을 먼저 학습·검증·테스트로 나눈 뒤 샘플을 만들어 같은 세션의 prefix가 여러 분할에 섞이지 않도록 한다. 현재 seed `42`의 샘플 수는 **40,093 / 5,028 / 5,000**이다. 입력은 최근 64개 행동을 사용하고 왼쪽 PAD로 길이를 맞춘다.

### 상품 ID 임베딩

ID 숫자의 거리는 상품 유사도가 아니다. `101`과 `102`라는 이유로 비슷하게 추천하지 않는다. ID는 학습 가능한 상품 벡터를 조회하는 인덱스다.

상품 벡터는 무작위 초기화 후 다음 상품 예측 손실을 통해 조정된다. 현재는 이미지 유사성이 반영된 행동 패턴을 통해 상품 관계를 간접적으로 배운다. CLIP 벡터로 ID 임베딩을 초기화하거나 모델 입력에 직접 연결한 것은 아니다.

### 행동·최근성 가중 평균

이벤트별 상품·행동 표현을 결합하고 다음처럼 집계한다.

$$
h_t = \operatorname{LayerNorm}(e_t^{product} + e_t^{action})
$$

$$
w_t = w_t^{action}\exp(-0.25d_t), \qquad
x = \frac{\sum_t w_t h_t}{\max(\sum_t w_t, \epsilon)}
$$

`d_t`는 가장 최근 행동에서 떨어진 유효 이벤트 수다. PAD는 제외한다.

| 행동 | 기본 가중치 |
|---|---:|
| PAD | 0.0 |
| PRODUCT_SELECT | 1.0 |
| FITTING_ADD | 1.5 |
| FITTING_REMOVE | 0.5 |
| WISHLIST_ADD | 2.0 |
| WISHLIST_REMOVE | 0.5 |

같은 종류의 행동 세 개라면 오래된 순서부터 최근성 가중치는 약 `0.61, 0.78, 1.00`이다. 따라서 순서를 전혀 무시하는 방식은 아니다. 다만 평균으로 압축하면서 복잡한 전이 관계나 반복 횟수 정보가 약해질 수 있다. 제거 행동의 가중치도 양수이며, 이전 추가를 명시적으로 취소하지 않는다.

행동 수·pooling 모드·최근성 감쇠·행동 가중치는 체크포인트에 저장해 학습·평가·추론에서 복원한다. PAD 제외, 최근 행동 우선, 행동 강도, 단일 이벤트, 전체 PAD 입력을 검증하는 테스트가 있다.

### 재귀 보정과 후보 점수

RecRec은 정적 증거 벡터를 바탕으로 사용자 선호 표현을 반복 보정하며, 증거에 연결된 correction gate를 유지한다. 상품 이미지나 상품 설명 자체를 수정하는 것이 아니다. 보정된 선호와 후보 상품 표현으로 점수를 계산하고 다음 상품 정답에 대한 cross-entropy로 학습한다.

새 데이터의 입력 형식이 기존과 같으므로 기본 RecRec 구조를 바꾸지 않고 재학습할 수 있다. 상품 임베딩·이력 처리·재귀 보정은 함께 학습되며, 재귀 보정만으로 부실한 데이터를 보완할 수 있다고 가정하지 않는다.

## 6. 선택적 콘텐츠 경로와 추천 후처리

`--content` 학습 옵션은 상품명·성별·카테고리·하위 카테고리·Zone·색상을 256차원 결정론적 feature hashing으로 표현한다. Projection으로 차원을 맞춰 ID 임베딩에 결합하며, 이력과 후보는 같은 `encode_products()`를 사용한다. 콘텐츠 feature와 projection은 체크포인트에 저장한다.

**이 옵션은 CLIP이나 SBERT를 활성화하지 않는다.** Feature hashing은 속성·토큰 일치를 표현하지만 사전학습된 텍스트 의미 관계를 직접 제공하지 않는다. SBERT는 선택적인 확장이다.

`src/inference.py`에는 카테고리 필터, 상품명 토큰·속성 일치 가점 등의 후처리가 있다. 기본 모델이 ID-only라는 것과 추천 API 전체가 상품 속성을 쓰지 않는다는 것은 다르다. 이미지 기반 데이터 생성 작업에서 API 후처리는 변경하지 않았다.

## 7. 체크포인트와 기존 평가 결과

### 현재 로컬 체크포인트

문서 재작성 시 `checkpoints/recrec_best.pt`에서 확인한 값이다.

| 항목 | 값 |
|---|---|
| 저장 epoch | 18 |
| 저장 validation loss | 2.6399231554500244 |
| 상품 임베딩 차원 | 128 |
| 행동 유형 수 | PAD 포함 6 |
| Pooling | action_recency |
| 콘텐츠 feature 사용 | false |
| 최근성 감쇠율 | 0.25 |

체크포인트에 학습 데이터 hash가 없어 **이 파일만으로 이미지 기반 새 데이터 사용 여부를 확정할 수 없다.** 따라서 재학습이 없었다고 단정하거나 저장 loss를 과거 실험과 비교해 개선됐다고 주장하지 않는다. 새 결과에는 데이터 hash, 체크포인트, 평가 후보 조건을 함께 기록해야 한다.

### 이전 합성 데이터의 비교 실험

다음은 `artifacts/evaluations/`에 보존된 이전 데이터의 실험 기록이다. **이미지 기반 새 데이터의 성능이 아니다.** Pooling 비교는 10 epoch 예산으로 수행했다.

| Pooling | HR@1 | HR@5 | HR@10 | NDCG@10 | MRR@10 |
|---|---:|---:|---:|---:|---:|
| Mean | 0.0261 | 0.1495 | 0.2947 | 0.1321 | 0.0839 |
| Action | 0.0269 | 0.1489 | 0.2961 | 0.1334 | 0.0851 |
| Recency | 0.0255 | 0.1432 | 0.2823 | 0.1275 | 0.0816 |
| Action × Recency | 0.0247 | 0.1467 | 0.2867 | 0.1292 | 0.0824 |

Action은 Mean보다 소폭 높았지만 최근성 가중치의 성능 개선은 확인되지 않았다. Metadata + Action × Recency의 기록은 `HR@10 0.2912`, `NDCG@10 0.1289`, `MRR@10 0.0807`이다. 지표별 결과가 다르므로 콘텐츠 추가가 모든 지표에서 더 좋거나 나쁘다고 일반화하지 않는다.

## 8. 현재 한계와 다음 검증

이미지 기반 합성 데이터는 디자인 취향을 가정한 초기 학습·시스템 검증 자료다. **이미지가 비슷하다는 것이 실제 고객의 다음 선택·피팅·찜을 뜻하지는 않는다.** 행동 확률과 탐색 비율도 실측값이 아니라 설계 가정이다.

같은 생성 규칙으로 만든 학습·평가 데이터에서 높은 성능을 얻어도 규칙을 잘 재현한 것일 수 있다. RecRec이 실제 고객 취향을 잘 예측한다는 증거로는 부족하다.

다음 방식을 같은 카테고리 후보와 동일한 성별·기조회 상품 처리 조건에서 비교해야 한다.

| 비교 방식 | 목적 |
|---|---|
| 무작위·학습 데이터 인기순 | 단순 기준 대비 효과 확인 |
| 관심 상품 이미지 벡터의 행동·최근성 가중 평균 | 이미지 유사도로 직접 추천했을 때의 품질 확인 |
| 새 합성 데이터로 학습한 RecRec | 학습과 재귀 보정의 추가 효과 확인 |

직접 이미지 추천과의 비교는 아직 완료된 결과가 아니라 다음 검증 계획이다. 기존 평가 명령 실행만으로 서비스와 동일한 단일 카테고리 평가가 완료됐다고 간주하지 않으며, 후보 제한 조건을 확인해야 한다.

추가로 남은 제약은 다음과 같다.

- 실제 timestamp가 없어 경과 시간 대신 이벤트 거리로 최근성을 계산한다.
- 사진의 각도·배경·색상 영향과 서로 다른 하위 카테고리의 이웃을 검토해야 한다.
- ID 기반 모델은 신규 상품 이미지 하나만으로 즉시 추천하는 구조가 아니다.
- 현재 평가는 세션 분할이다. 신규 상품 holdout에서는 동일 이미지 상품 31·127을 같은 그룹으로 묶어 누출을 방지해야 한다.
- 실제 로그 수집 후 재학습·평가하고, 필요할 때 이미지 벡터의 직접 입력이나 이력 표현 개선을 비교한다.

## 9. 실행 방법과 주요 파일

프로젝트 루트에서 실행한다. 이미지 임베딩 환경 설치는 [이미지 유사도 문서](image-similarity.md)를 따른다.

```powershell
# 이미지가 바뀐 경우 임베딩과 보고서 재생성
.\.venv-image\Scripts\python.exe -m src.image_similarity

# 이미지 기반 합성 데이터 생성
python -m src.synthetic_image_generator

# 현재 synthetic_interactions.jsonl로 기본 ID-only RecRec 학습
python -m src.train

# 현재 데이터와 체크포인트로 평가
python -m src.evaluate
```

생성기는 기존 데이터 내용이 다르면 `artifacts/synthetic_backups/{SHA256}.jsonl`에 백업한 뒤 교체한다. 기본 학습은 최대 30 epoch이며 `checkpoints/recrec_best.pt`를 갱신한다. 기존 체크포인트 보존이 필요하면 학습의 `--checkpoint` 옵션으로 별도 저장 경로를 지정하고 평가에도 같은 경로를 전달한다.

`python -m src.synthetic_generator`는 이전 속성 기반 생성 명령이므로 이미지 기반 데이터 재생성에는 사용하지 않는다.

| 파일 | 역할 |
|---|---|
| `src/image_similarity.py` | CLIP 벡터와 이미지 비교 보고서 |
| `src/synthetic_image_generator.py` | 이미지 기반 단일 카테고리 합성 세션 |
| `src/synthetic_generator.py` | 기존 생성기와 재사용 행동 함수 |
| `src/dataset.py` | 세션 분할·다음 상품 학습 샘플 |
| `src/recrec.py` | 상품·행동 표현, pooling, 재귀 보정, 손실 |
| `src/product_features.py` | 선택적 metadata hashing |
| `src/train.py`, `src/evaluate.py` | 학습 및 평가 |
| `src/inference.py` | 추론과 추천 후처리 |
| `tests/test_weighted_pooling.py` | PAD·행동·최근성 집계 검증 |
| `tests/test_synthetic_image_generator.py` | 생성 재현성·선택 효과·상태 검증 |
